# Architecture Docs — ระบบติดตามความคืบหน้าโครงการวิจัย

_ดัชนีรวมเอกสารสถาปัตยกรรมของระบบนี้ (สถาปัตยกรรม = พิมพ์เขียวว่าระบบประกอบด้วยอะไร ทำงานยังไง เพราะอะไร) เอกสารทั้งหมดเรียงจากคำถามง่ายไปยาก ตั้งแต่ "ระบบนี้ทำอะไร" จนถึง "โค้ดแต่ละส่วนเรียกกันยังไง"_

ระบบนี้คือ backend (ส่วนหลังบ้านที่รันบนเซิร์ฟเวอร์ ผู้ใช้ไม่เห็นหน้าจอโดยตรง) เขียนด้วย NestJS ซึ่งทำงานร่วมกับ frontend (ส่วนหน้าบ้านที่ผู้ใช้กดปุ่ม อยู่ใน repo `Frontend` แยกต่างหาก) โค้ดถูกจัดแบบ modular monolith — คือรวมทุกอย่างไว้ในโปรแกรมเดียว แต่แบ่งเป็นโมดูลย่อยตามหน้าที่ ไม่ได้ทำเป็นหลายบริการแยกกัน เพราะโหลดของระบบไม่สูง แหล่งข้อมูลต้นทางของทุกเอกสารคือ `docs/sources/project-erd.md` (ผังฐานข้อมูลของระบบ)

## ลำดับการอ่านที่แนะนำ

1. **[requirement.md](requirement.md)** — เข้าใจก่อนว่าระบบต้องทำอะไร ใครใช้ และมีกฎอะไรบ้าง
2. **[c4/c4-context.md](c4/c4-context.md)** — ภาพกว้างที่สุด: ระบบของเรามีใครใช้ และคุยกับอะไรภายนอกบ้าง
3. **[arc42.md](arc42.md)** — ฉบับเต็ม พร้อมเหตุผลของทุกการตัดสินใจ (ศัพท์เทคนิคจะถูกอธิบายครั้งแรกที่เจอ)
4. **[c4/README.md](c4/README.md)** — ซูมเข้าเป็นภาพ ทีละระดับ ตั้งแต่ภาพรวมถึงโครงสร้างโค้ด
5. **[sequence-diagrams.md](sequence-diagrams.md)** — เจาะ flow ที่ซับซ้อนที่สุดของระบบ เช่น กรรมการอนุมัติแผนตอนที่นักวิจัยแก้ของเล็กระหว่างรออยู่

## จุดตัดสินใจสำคัญที่ต้องรู้ก่อนอ่าน

เรื่องเหล่านี้ปรากฏซ้ำในทุกเอกสาร จึงขอสรุปสั้น ๆ ไว้ก่อน (รายละเอียดเต็มอยู่ใน arc42.md และเอกสาร C4):

- **แผนมีสองแบบ** — แบบ**มีสังกัด** (institutional) ต้องให้กรรมการอนุมัติก่อนจึงมีผล โดยกรรมการเพียงคนเดียวตัดสินก็เพียงพอ ส่วนแบบ**ไม่มีสังกัด** (independent) นักวิจัยกดสรุปเองได้ ไม่ต้องรอใคร
- **การแก้แผนถูกจัดเป็นสองระดับ** — แก้ของเล็กที่ไม่กระทบสาระแผน (minor) ระบบรวมเข้าเวอร์ชันที่มีผลอยู่ทันที แต่ถ้าแก้ของสำคัญ (major) สักจุดเดียว ทั้งชุดจะกลายเป็นเวอร์ชันใหม่ที่ต้องรอกรรมการ
- **หลัก preservation** — ข้อมูลที่บันทึกการทำงานจริงจะไม่ถูกลบทิ้งเด็ดขาด ระบบทำได้แค่เก็บพักไว้ (archive) หรือยกเลิกโดยจดเสมอว่าอะไรถูกยกเลิก เพราะอะไร
- **ตรรกะธุรกิจแยกออกจาก framework** — ส่วนที่คำนวณกฎของระบบ (domain engine) เขียนเป็น pure function คือฟังก์ชันที่รับข้อมูลเข้า–ส่งออกเท่านั้น ไม่แตะฐานข้อมูลหรือเครือข่ายเอง ทำให้ทดสอบง่าย และเปลี่ยนเครื่องมือภายนอกทีหลังได้ไม่ต้องแก้กฎธุรกิจ
